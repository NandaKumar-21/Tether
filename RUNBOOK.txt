-----------------------------------------------
ADB IS NOT ON PATH. Use the full path:
-----------------------------------------------

$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"

Paste that once into the PowerShell window and
every "& $adb ..." line below will work.


===============================================
BEFORE YOU GO ON STAGE
===============================================

1. Phone plugged in, unlocked, screen on.
2. Run the full demo once to warm the model:

   powershell -ExecutionPolicy Bypass -File scripts\demo.ps1

3. Leave it. Do NOT reboot after this.

Warming matters: cold load is 22-25s of silence,
warm is 0s.

===============================================
IF SOMETHING BREAKS
===============================================

ANSWER COMES BACK EMPTY
-----------------------
   powershell -ExecutionPolicy Bypass -File scripts\fix.ps1

Takes 25 seconds. Wipes the corrupt MediaPipe
GPU cache, reloads, prints READY.
This is the ONE known cause of empty replies.


CONNECTION REFUSED / CURL HANGS
-------------------------------
   & $adb forward tcp:8080 tcp:8080

The forward is dropped by unplugging the cable
or by a reboot. Re-run it.


APP NOT RUNNING
---------------
   & $adb shell am start -n com.tether.app/.MainActivity

Server auto-starts with the app. Wait ~22s for
the model, then check:

   curl.exe -s http://127.0.0.1:8080/health


PHONE REBOOTED
--------------
Just run demo.ps1. It handles a phone that comes
back online with wifi on. Verified.
The model file survives reboot. Never re-push it.


DEVICE NOT FOUND
----------------
   & $adb devices
Unplug, replug, unlock the phone, accept the
USB debugging prompt if it appears.


===============================================
IF A JUDGE DOES NOT BELIEVE IT IS ON-DEVICE
===============================================

Hide the model and show it break:

   & $adb shell mv /data/local/tmp/llm/gemma3-1b-it-int4.task /data/local/tmp/llm/hidden
   & $adb shell am force-stop com.tether.app
   & $adb shell am start -n com.tether.app/.MainActivity
   curl.exe -s http://127.0.0.1:8080/health

Shows:  "model_loaded":false
        "model_path":"not found"

And a request returns:
   "model file not found or unreadable"

Put it back:

   & $adb shell mv /data/local/tmp/llm/hidden /data/local/tmp/llm/gemma3-1b-it-int4.task
   & $adb shell am force-stop com.tether.app
   & $adb shell am start -n com.tether.app/.MainActivity

Wait 25 seconds, then verify:

   curl.exe -s http://127.0.0.1:8080/health

Must show "model_loaded":true before you continue.

DO NOT do this unless challenged. It costs 60s.

  GET  /health


===============================================
IF ASKED: WHERE DOES THE ANSWER COME FROM
===============================================

curl on laptop
  -> adb forward, over the USB cable
  -> phone port 8080, NanoHTTPD in a
     foreground service
  -> TetherServer routes /v1/chat/completions
  -> prompt wrapped in Gemma 3 turn format
  -> LlmEngine.generate
  -> MediaPipe native, Adreno GPU via OpenCL
  -> weights read from
     /data/local/tmp/llm/gemma3-1b-it-int4.task
  -> answer back up the same path

It is computed one token at a time from 1
billion int4 parameters. Nothing is cached and
nothing is retrieved.


===============================================
DO NOT DO THESE ON STAGE
===============================================

- Do not reboot the phone. Cold load is 25s.
- Do not ask for long code generation. The 1B
  model rambles and emits stray characters.
  Good prompts, all verified:
    What is a race condition
    What is a mutex
    TCP vs UDP in one sentence
    Capital of Japan
    17 times 3
- Do not trust the airplane mode icon alone.
  The ROM re-enables wifi after a reboot.
  demo.ps1 disables the radios every run.
- Do not unplug the USB cable. It drops the
  adb forward.
